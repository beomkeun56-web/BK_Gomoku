# 설계 결정·변경 이력 (대화 기반 인수인계)

이 문서는 원격 웹 세션에서 합의된 **설계 의도와 그 이유**를 기록한다.
(코드 *무엇*은 `git log`와 `CLAUDE.md`에, *왜*는 여기에.)
새 작업을 시작하기 전에 관련 항목을 읽고, 이미 내린 결정을 되돌리지 말 것.

## 게임 디자인 큰 방향

- **4가지 방향을 현실적으로 섞는다**: ①명분(권력으로 뭘 이루려는지) ②대가(무리한 선택의 후과)
  ③건설(법안·민생·연설·진짜 동맹) ④현황. 공격·비리 캐기는 양념이지 전부가 아니다.
- **실패는 드물게**: 정해진 주기로 강제하지 말 것. *플레이어의 무리한·잘못된 선택의 결과*로만
  가끔 일으키고, 닥쳐도 다음에 잘 고르면 만회할 여지를 남긴다. 신중히 두면 성공해야 한다.
- **게이트 체이닝 금지**: 한 서브목표(약점·문서·인물 포섭)는 **2~3턴 내 결판**. 'A하려니 B부터 →
  B하려니 C부터' 식 무한 전제조건 금지. 막히면 부분성과로 다음 국면 진행.
- **리스크는 판을 뒤흔드는 하드 게이트가 아니라 드라마 엔진**. 비리·막장·사이다를 할 수 있게,
  리스크가 너무 크게 작용해 플레이를 막지 않도록.

## 서사 구조 (5막 사다리 · 단일 저자)

- 1부(초선→대선) ~300턴 / ~10년. **1막에서 시작**.
- 막마다 고정 상수(관문/통과조건/수순). 통과조건은 스탯 임계로 표현하고, 이월되는 만큼
  뒤 막일수록 높게(턴 예산에 맞춰). 막·목표·다음 관문은 항상 같은 막, 관문 치르면 즉시 갱신.
- **단일 저자 원칙**: 상태판 = 스토리. GM이 스탯·날짜를 스토리와 함께 emit하고 앱은 표시만.
  앱이 멋대로 전술/수순을 만들지 않는다(과거 '수순'을 앱이 생성하려다 전술로 흘러 실패 → A안에서 폐기).
- **상태판 A안**: 종합 / 목표 / 지금 / 필요(통과조건 vs 현재, 부족분) / 할일 / 지표 / 누락
  → 이후 정리되어 종합/다음(D-day)/목표/필요/할일/지표. '수순'은 필요·할일로 대체됨.

## 시간 모델

- 날짜는 **매 턴**이 아니라 **본문에서 실제로 흐른 시간**에 맞춰 전진한다.
  같은 순간 연속 장면이면 그대로, 다음 날·며칠 뒤로 넘어가면 그만큼 전진.
- 하루엔 **현실적으로 가능한 일만**. 여러 날 걸릴 일은 여러 날에 나눈다.
- D-day는 앱이 계산(현재날짜·일정날짜 두 개로). GM은 `D-NN`을 직접 쓰지 않는다.
- 제목·소제목 끝에 게임 내 날짜·시각을 〔 〕 작은 회색 글씨로.

## 선택지 (고정 3종)

- ①목표 경로(가장 부족한 통과조건 스탯을 올리는 정상 수 — '할일'과 일치)
- ②더러운 수(비리·공작·협박 한 방)
- ③상황별 제3의 결(방어·명분·관망·동맹 등)
- 각 선택지 끝에 스탯 효과 태그 〔방향↑/↓·크기〕(숫자 금지).
- **중요한 균형 결정**: '더러운 수'가 리스크만 키우면 아무도 안 고른다 →
  **더러운 수 = 보상이 더 크고 빠른 지름길**, 리스크↑·명분↓는 *지연된* 대가로. 〔↑↑·리스크↑〕.

## 스탯 (재조정됨)

- 4종: 세력 / 민심 / 명분 / 리스크 (0~100).
- 시작값 낮게, 상승 느리게, 통과 임계는 턴 예산에 맞춰 높게. 체감 정체는 금지(집중 시 최소 +1).
- 변화는 이번 사건 결과 ±1~4, 큰 사건도 ±6~10, +10 초과 금지. 70↑·85↑에서 체감 둔화.
- (과거 버그: 시작값이 높고 임계가 낮아 10턴 안에 3막까지 갔다 → 전면 재조정.)

## 톤 / 프로바이더별 보정

- 모드는 **수치 다이얼만**(자극/충격/코믹/사이다/치정·로맨스). 프리셋 제거.
  다이얼은 양 프로바이더 공통 적용. 큰 구도는 모드가 세져도 유지.
- **Claude는 기본이 점잖아 약하다** → `providerStyle`에서 욕설·MZ 말투·코믹을 **세게 풀어라**.
  특히 코믹(어이없는/상황/대사 코믹)을 매 턴 확실히. 성적 묘사·로맨스도 확대.
- **Gemini는 인물 묘사를 동일 문구로 반복**하는 경향 → `providerStyle`에서 외모·관능 묘사를
  **한 줄로 줄이고 반복 금지**, 아낀 분량은 사건·전개에. (※Gemini엔 욕·코믹 지시가 없음 —
  필요하면 "묘사만 줄이되 욕·코믹은 수치대로 유지" 한 줄 추가 검토.)
- **토큰 낭비 주의**: 원치 않는 출력은 *잘라내지 말고*(이미 생성=과금) 프롬프트로 *생성 자체를 막아라*.

## 비용 / 캐시 (중요)

- 시스템 프롬프트는 **고정만**(`sysText()`=`SYSTEM_PROMPT`). 매 턴 바뀌는 톤·시간·보정 지시는
  `buildApiMessages()`가 **마지막 user 메시지 끝**에 붙인다.
- 이유: 시스템 prefix가 바뀌면 그 뒤 대화 전체가 implicit 캐시에서 빠져 **비용이 두 배로** 튄다.
  (실제로 변동 리마인더를 시스템에 넣었다가 Gemini 캐시가 깨져 과금 폭증 → 끝으로 이동해 해결.)

## Gemini 직접연결 "빈 응답" (해결됨 — 건드리지 말 것)

- 근본 원인: `readSSE`가 이벤트 경계를 `\n\n`으로만 split했는데 **직접 Gemini는 CRLF(`\r\n\r\n`)** 사용
  → 파싱이 0건이 되어 빈 응답. **`/\r?\n\r?\n/`로 split**해서 해결(LF·CRLF 둘 다).
- 부수: `safetySettings` BLOCK_NONE, thinking 한도, 비스트리밍 폴백, 진단(`lastGemDiag`) 추가.

## 삽화

- 텍스트와 **병렬 생성**: GM이 첫 줄에 `[IMG]...[/IMG]`(영어 60~90단어)를 주면 즉시 이미지 생성 시작,
  완성되는 즉시 상태판/본문 아래 표시. GM이 안 주면 본문으로 폴백.
- `geminiImage`는 `safetySettings` BLOCK_NONE.

## 후처리 (앱 sanitize)

- 본문에서 실존 연예인·유명인 likeness('OO를 닮은') 제거 — 블록리스트.
- C컵·미니스커트·글래머 등 치장 상투 구절 제거. 상태판 태그(`<prog><goal><stat>` 등) 제거.

## 지표 색 (v5.37, 최신)

- 값 색: **리스크는 항상 빨강**(경고). 그 외엔 높으면 파랑·낮으면 빨강(임계 60/40).
- 변화량 색: **전 항목 동일 — 오르면 파랑, 내리면 빨강.** (과거 리스크만 반전시켜 혼란 → 제거.)

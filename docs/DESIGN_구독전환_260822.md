# 국가의시대(권력의 길) 구독 전환 설계 — 2026-08-22

## 목표·제약 (범근님 지시 원문 기준)
1. 목표: 게임의 LLM 호출을 API 과금 → **맥미니 로컬 claude 구독(소넷)** 경유로 전환.
2. 이미지: 웹앱에 삽화 출력. ★지시는 "그록 이미지"였으나 실측 결과 그록 CLI에 이미지
   모델이 없음(models_cache에 grok-4.5/4.6 텍스트뿐) → **엔진 교체 가능한 구조**로 만들고
   1차 엔진은 기존 구글 키(Gemini 이미지, 장당 약 50원, 앱에서 토글). 그록은 xAI API 키
   확보 시 서버 한 곳만 바꿔 교체.
3. 응답 체감 최소화: **스트리밍**(SSE) + **상주 워커**(시스템 프롬프트 캐시).
4. 불가침: 번역 배관(bktrans_sonnet_daemon.py·기존 server.py 번역 경로·번역 터널) 무손상.
   기존 게임 설계결정(docs/DECISIONS.md) 위반 금지. API 키·bk_key를 저장소에 커밋 금지.

## 구조 (G1 기능그래프)
```
게임 index.html ──(A) HTTPS SSE──> 서울 server.py /game ──(B) 역터널 8768──> 맥 game_daemon.py :8767 ──> claude CLI(소넷, 상주)
        │                                    │
        └──(C) HTTPS──> server.py /game_image ──(D)──> Google Gemini 이미지 API
```

## 엣지 계약 (각 3줄: 무엇이/도착·신선도/확인법)
- **A. 앱→서버 /game**: POST JSON `{sid, reset?, user?, replay?[]}` + 헤더 `X-BK-KEY`.
  응답은 즉시 시작되는 SSE(`data: {"t":"토큰"}` 반복 → `data: {"done":true}` / 오류 `{"err":..}` / 세션소실 `{"need_replay":true}`).
  확인: curl -N 으로 토큰이 흘러나오는지, 오류 시 err 프레임.
- **B. 서버→데몬(역터널)**: 서버가 `http://127.0.0.1:8768/game` 로 같은 JSON 전달, 응답
  chunk를 그대로 앱에 중계(버퍼링 금지). 터널은 launchd 상시(autossh형 재접속).
  확인: Vultr에서 `curl 127.0.0.1:8768/ping` 이 데몬 버전을 반환.
- **C. 앱→서버 /game_image**: POST `{prompt}` (영어, [IMG] 블록 내용) + X-BK-KEY.
  응답 `{"b64":"...", "mime":"image/png"}` (30초 내). 실패는 `{"err":..}` — 앱은 삽화 없이 진행(격리, 차단 아님).
- **D. 서버→Gemini 이미지**: config.json의 gemini_api_key 사용, 모델은 config
  `game_image_model`(기본 gemini-2.5-flash-image). 교체(그록 등)는 이 한 곳.
  확인: 서버 단독 curl 시험으로 b64 수신.

## 데몬 세션 모델 (핵심 결정)
- 상주 claude 프로세스 1개/세션(범근님 1인 플레이 전제, 세션표 {sid: proc}).
  시스템 프롬프트=앱이 replay/최초에 보내는 system 텍스트(=게임 SYSTEM_PROMPT). 첫 턴만 올라가고 이후 캐시.
- `reset:true` → 기존 proc 종료 후 새로 기동. 데몬 재시작 등으로 sid 미존재 →
  `need_replay` 응답 → 앱이 대화 전문 replay 배열로 재구축(앱은 이미 전체 기록 보유).
- 모델: 소넷 고정(오푸스 금지 — 한도 보호, 번역데몬 운영규칙과 동일). MAX_THINKING_TOKENS=0 + 출력억제 규칙.
